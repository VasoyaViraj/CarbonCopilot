# EcoTrace AI — Business Rules

## BR-01 Deterministic Emission Calculation

```text
CO2e = Activity Quantity × Emission Factor
```

The numerical calculation is performed by backend/tool code, not generated by the LLM.

## BR-02 Emission Factor Versioning

An emission record stores the emission factor used for its calculation so historical results remain explainable when factors change.

## BR-03 Hotspot Contribution

```text
Contribution % =
Process Emissions / Total Emissions × 100
```

Processes are ranked descending by contribution.

## BR-04 Hotspot Severity

Default thresholds:

| Contribution | Severity |
|---:|---|
| >40% | CRITICAL |
| 25–40% | HIGH |
| 10–25% | MEDIUM |
| <10% | LOW |

Thresholds should be configurable.

## BR-05 Abnormal Emission Intensity

```text
Emission Intensity = CO2e / Production Quantity
```

A simple hackathon anomaly signal may compare current intensity with a historical rolling average.

Example:

```text
7-day average → 0.10 tCO2e/tonne
Current        → 0.18 tCO2e/tonne
```

The system can label this:

> Potential abnormal emission intensity detected.

This is not ML and should not be presented as a certified leak detector.

## BR-06 Recommendation Score

Default:

```text
Score =
0.40 × Environmental Impact
+ 0.25 × Financial Benefit
+ 0.20 × Feasibility
+ 0.15 × Circularity
```

Normalize component scores to a common scale before combining.

## BR-07 Scenario Isolation

Scenario changes never overwrite baseline activity/emission data.

## BR-08 Scenario Reduction

```text
Reduction = Baseline − Projected

Reduction % =
Reduction / Baseline × 100
```

If baseline is zero, reduction percentage must not divide by zero.

## BR-09 Payback

When valid:

```text
Payback Years = Estimated Cost / Annual Savings
```

If annual savings are zero or unavailable, payback is `N/A`.

## BR-10 AI Grounding

AI-generated claims about factory conditions must be grounded in:
- Database data.
- Tool outputs.
- Explicit user-provided values.

The model must not invent missing factory measurements.

## BR-11 Uncertainty

If an input or recommendation is estimated, the response should state:
- Assumption.
- Estimated value.
- Confidence/limitation.

## BR-12 Simulation Label

Every simulated reading must be marked as simulated in the UI/API.

## BR-13 Access Control

Users cannot access another organization's factory data merely by changing a URL ID.

## BR-14 CSV Validation

Rows with invalid required fields should:
- Be rejected or quarantined.
- Provide row-level error information.
- Never silently create incorrect emissions.

## BR-15 Recommendation Explanation

Every recommendation should expose:
- Why recommended.
- Estimated reduction.
- Estimated cost.
- Estimated savings.
- Payback.
- Assumptions/confidence.

## BR-16 No Autonomous Plant Control

The MVP only recommends actions. It does not directly control industrial equipment.
